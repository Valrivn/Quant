MODIFICATION: Adopt the hermes hybrid as the build base, then restructure into THREE test strategies with risk-constrained weight optimization:
1. STATIC-40/20/20/20 (CEO version): fixed 40/20/20/20 weights, no re-optimization. This is the "static (my version)" baseline.
2. STATIC-after-ML: the gradient-descent engine finds the optimal weights once (in-sample fit, pre-registered train/OOS split), then those weights are held STATICALLY for the whole window.
3. ADAPTIVE (non-static): weights are re-optimized dynamically through the window, with REQUIRED risk optimization.
Risk optimization is mandatory for the non-static variant: the objective is MAXIMIZE SHARPE; weights are PUNISHED when too risky; hard constraint that the portfolio is down at most 30% at any point in time (max drawdown <= 30% at every point).
Order of work: (a) run the static 40/20/20/20, (b) dynamically find the optimal ratio via the optimizer, (c) run that ratio statically (STATIC-after-ML), (d) run the adaptive re-optimizing version. The comparison set is therefore: SPY baseline, STATIC-40/20/20/20, STATIC-after-ML, ADAPTIVE, plus the opportunistic-only baseline from the brief.
Unchanged from the hybrid: everything pre-registered in config/weights_diversification.yaml before any run (train/OOS split, risk penalty, 30% DD constraint, thresholds); profit-change OR-gate flag with fee-churn attribution; small/mid via liquid ETF proxies (MDY/IWM) under the 10-15% floor; cash measured not maximized; auditor OOS/no-hardcoding discipline; cash-shortfall relocation reported as an ablation.
RATIONALE: The CEO wants both worlds tested — his fixed mix vs the ML-found weights held statically vs the same engine adapting over time — and requires the adaptive engine to be risk-aware (Sharpe objective, risky-weight penalty, hard 30% max-drawdown bound) so it is honest about drawdown.
