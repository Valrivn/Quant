# Audit — Phase-3 risk-constrained ML allocator (D-20260803-005)

Auditor gate (hard requirements per ruling D-20260803-005): NO hardcoded
weights/picks/params in the backtest; every threshold pre-registered in
`config/weights_diversification.yaml` BEFORE any run; in-sample fit on a
pre-registered trailing segment + OOS validation on a held-out segment; hard
30% max-drawdown constraint honored. Verdict: **PASS** with documented caveats.

## 2. OOS validation (mandatory)

- STATIC-after-ML fit uses ONLY data at/under `train_end` (2022-12-31) minus the
  21d embargo; the resulting weights are held statically for the whole window.
  Validation on the held-out 2023+ segment: **Sharpe 1.90, maxDD -9%** (vs
  0.83 / -33% for SPY in the same window) — the in-sample fit did NOT overfit.
- ADAPTIVE re-fits on a trailing 3y embargoed window at every rebalance date
  (no lookahead by construction); every change must clear the friction gate.
- Stable-dividend basket and macro state are trailing-only (Phase-1/2
  discipline unchanged).

## 5. Caveats

1. SEC XBRL + FRED cross-checks degraded to NA (EDGAR/FRED unreachable); must
   be exercised when reachable.
2. STATIC-after-ML OOS segment row in the printout shows the full-window
   end_value/gain/fees (segment metrics Sharpe/maxDD/ann_return are
   segment-correct) — cosmetic, not a data error.
3. The optimizer converged near the same corner for STATIC-after-ML and
   ADAPTIVE in this window; that convergence is window-specific evidence, not
   a guarantee.
4. Dividend yields remain static annual estimates (measurement only).
5. 2018-2026 is a US-large-cap-dominated window; "does it beat SPY" is
   window-specific.
