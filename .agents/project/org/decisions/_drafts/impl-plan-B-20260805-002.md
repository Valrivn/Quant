## Phase 2 — Reward metric: alpha − λ·transaction cost (allocator objective)
- Objective at each rebalance: maximize `R = alpha − λ·tc·turnover`, where `alpha = ann_return(strategy) − ann_return(SPY)` over the trailing window, `tc` = per-unit-turnover cost (fees + slippage, ~10-15 bps, pre-registered), `turnover` = fraction of NAV traded at the rebalance, `λ` = pre-registered penalty (0.3 default; sensitivity 0.1-1.0 reported, never fit).
- The optimizer keeps existing bounds (state equity weights, sleeve bounds, 30% max-DD hard constraint). Reward replaces raw return as the selection objective inside `optimize_return_weights`.
- Transaction minimization is enforced two ways: the reward penalty AND a hold-band — do not trade if `|Δtarget| < tc` or if the expected alpha gain is below the trade's cost (formalizes RM-FINAL's existing "hold" gate; makes it a first-class knob in `weights_diversification.yaml`).
- **Double descent (capacity/overfit control):** complexity axis = {trailing-window length, number of state buckets, momentum lag}. For each complexity level compute train/OOS reward; select the complexity at the top of the generalization curve (where OOS reward stops improving) on the TRAIN segment only (`<= train_end`), then lock it. Report the full complexity-vs-OOS-reward curve so the CEO can see overfitting onset — never select the complexity that maximizes the reported full-window result.

## Phase 3 — Bayesian updating of P(strategy beats SP500)
- Prior: `p ~ Beta(a0, b0)` over `p = P(win a window vs SPY)`. Set `a0=11, b0=9` (mean 0.55, wide) — encodes the CEO's belief ("my strategy will beat SPY") WITHOUT letting the prior dominate evidence. `a0,b0` live in config, pre-registered.
- Likelihood: Bernoulli win/loss per NON-OVERLAPPING window (1Y), refreshed at each rebalance. Effective-sample correction for rolling-window overlap if rolling windows are used instead.
- Update: `Beta(a0 + wins, b0 + losses)`; report posterior mean + 90% credible interval in the dashboard and in every backtest report.
- Decision gate: risk-on / buy-more / de-risk actions only trigger when the posterior mean crosses pre-registered thresholds (e.g., >0.60 to stay fully risk-on, <0.45 to defensively de-risk) — this is the "conviction-scaled allocation." Thresholds are config knobs, not fit.
- This is the honest version of "statistics with Bayesian updating": the CEO's confidence is a live posterior, not an opinion.

## Phase 4 — Monte Carlo forward simulation on top of the current system
- Reuse the blueprint's non-negotiable stochastic core: Bernoulli shock filter (Damodaran ICR -> default prob), Poisson black swan (regime-aware λ from credit spreads), plus a residual model (GARCH(1,1) or block bootstrap on sleeve residuals) for ordinary market randomness.
- Procedure: (1) fit residuals conditioned on current regime state; (2) draw N=2000 forward paths (1m/3m/6m horizon) of sleeve returns; (3) run the CURRENT allocator forward on each path; (4) report distribution vs SPY: P(beat SPY), median/most-likely excess, worst-case, 5% VaR, max drawdown.
- **Backtest first:** validate MC calibration on history — realized OOS returns must fall inside the MC percentile bands at the claimed coverage (e.g., 90% band -> ~90% coverage). Report calibration curve; do not ship MC outputs as "prediction" until calibration passes.
- Scope guard: MC models KNOWN dynamics and their uncertainty; it cannot predict unknown unknowns. The dashboard labels it "distribution, not forecast."

## Phase 5 — Markov chain over Peter Lynch lifecycle states (predict + prepare)
- The blueprint already declares a 6-state Markov lifecycle (FAST_GROWER, STALWART, CYCLICAL, TURNAROUND, SLOW_GROWER, ASSET_PLAY). Operationalize it on the equity basket using existing fundamentals data (valuation_alpha XBRL datastore, SEC): growth rate, PE, ROE, dividend, cyclicality -> one state per name per month (PIT, no lookahead).
- Estimate the transition matrix P_ij from monthly observations (start-of-OOS only), compute stationary distribution + next-month state probabilities, and an aggregate regime index (share of names in growth vs defensive states).
- **Preparation action:** aggregate shift toward defensive states (STALWART/ASSET_PLAY) -> tilt the equity complex to quality/dividend names; shift toward growth/cyclical -> tilt to momentum. This is a SECOND regime signal, orthogonal to the FRED credit-spread state; fuse via the existing `data_fusion`/`bayesian_calibration` (Qualitative pillar) with provenance.
- Validation: out-of-sample transition accuracy + stability (transition matrix must be stable across eras, else the Markov assumption is violated and the layer is disabled with a report).
- "High statistics -> predict/prepare": the system prepares only when next-state probabilities are concentrated (low entropy); at high entropy it stays neutral and says "unpredictable."
