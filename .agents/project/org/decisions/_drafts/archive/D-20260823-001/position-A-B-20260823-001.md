POSITION: Build a five-phase PIT sandbox whose architecture enforces hard source isolation from day one, uses human-labeled corpora (Financial PhraseBank + SemEval-2017 T5 + Strux) as the sole auto-grader replacing all manual scoring, pre-registers every success bar in config/weights*.yaml before a single row is read, and gates each phase through conductor (≥90%) before advancing — so the final PASS/FAIL verdict on pipeline sentiment skill is fully falsification-first and sim-guardian-defensible.

REASONS:
1. PIT sandbox mechanics — all sources ingested through a timestamped DB-WAL layer with a per-row `available_as_of` field; any row whose label or score was not available PIT-clean on that date is quarantined to a `_excluded` partition tracked in the data-status ledger; no feature crosses partition boundaries.
2. Source-isolation ablation matrix — five columns (VERIFIED-only, RAW-only, LM-dict, Chen-Zimmermann controls, full pipeline) run in lock-step on identical date ranges; each column is a separate experiment ID with its own SHA-256 manifest entry; head-to-head F1/Spearman vs. the mechanical baseline is recorded before any cross-source blending is permitted.
3. Verified-vs-raw evaluation replacing manual grading — Financial PhraseBank (~4.8k sentences), SemEval-2017 T5, and Strux forward-return labels serve as the grading oracle; pipeline output is scored automatically against these corpora; the grading script is frozen and hash-logged before any model touches it; no human hand-grades during the run.
4. Pre-registered bars + tuning protocol — before Phase 1 executes, `config/weights_sentinel_bars.yaml` records: minimum F1 ≥ 0.62 vs. LM-dict baseline on VERIFIED set, Spearman ≥ 0.15 on Strux forward-return labels, ablation lift ≥ 5 pp F1 for full pipeline over RAW-only; tuning (hyperparams, weight blends) is unlocked only after all three bars are recorded as FAIL or PASS, never before.
5. Phased build — Phase 1: PIT DB layer + data-status ledger (conductor gate); Phase 2: grading oracle freeze + ablation harness (conductor gate); Phase 3: baseline runs for all five ablation columns (conductor gate + verdicts recorded); Phase 4: tuning pass if warranted; Phase 5: sim-guardian audit of SHA-256 manifest + final PASS/FAIL report.

RISKS:
1. Strux transcript coverage is sparse pre-2017; if the VERIFIED set is too thin on bear-regime dates (2020, 2022) the grading oracle may be underpowered and the verdict unreliable — mitigation: report coverage statistics per regime window before accepting any verdict.
2. Chen-Zimmermann factors as controls introduce a cross-source dependency if their vintage dates are not PIT-aligned; a single misaligned control variable silently contaminates every ablation column — mitigation: each factor's `available_as_of` must be verified in the data-status ledger in Phase 1, or the factor is quarantined.

BLIND-SPOTS:
- Did not verify whether idleengine's 33k-call corpus has a machine-readable PIT timestamp field or requires manual dating; if timestamps are absent, the RAW-only ablation column may be unrunnable.
- Did not verify that Financial PhraseBank's license permits automated grading use in a commercial research context; if restricted, the grading oracle loses its strongest component.
