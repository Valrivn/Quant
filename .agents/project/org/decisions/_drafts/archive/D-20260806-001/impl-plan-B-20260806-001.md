### 2.1 P1 — Sandbox (zero pipeline contact)
- Runs ONLY on the branch, ONLY sandbox tables, ONLY research outputs. No
  production state read (except public read-only interfaces), no writes outside
  `db/schema_discovery.py` tables.
- For each source, sample the mention stream (structured: up to N=500 validated
  tickers per source per cycle; video: sandbox batch of up to N=200) and record
  pass-through: raw mention → ticker validated → qualitative engine pass
  (multi-source Bayesian fusion + qualitative_scoring + quant baseline +
  selectivity stage D-20260803-001 + Glassdoor continuous tilt D-20260802-FINAL).
- **Deliverable:** pass-through census table per source (mentions, validated,
  gated, pass %) + reasons histogram for rejects. This is the evidence that
  decides the video gate and calibrates expectations for P3 coverage.

### 2.2 P2 — Deterministic ranker
- See SEC 3.4 for the score. Tests prove: identical input → identical output;
  no `random`/`np.random` in `discovery/` (grep-asserted in CI); deterministic
  tie-break (topic priority, then lexicographic ticker); config completeness.
- Concept separation goes live: concept rows can only enter the research
  backlog, never candidate lists (SEC 3.5).

### 2.3 P3 — Integration ablation on the branch
- `discovery/harness.py` runs TWO configurations on the RM-FINAL pipeline:
  1. **A = baseline** (RM-FINAL, untouched) — must reproduce baseline bytes.
  2. **B = baseline + discovery candidates** — at each monthly cycle, the
     deterministic ranker's top-k candidates (post full pass) may enter the
     candidate universe under pre-registered caps (SEC 7.4).
- **Seed control:** any stochastic component in the pipeline (MC paths, block
  bootstrap) uses the SAME seeds across A and B so the delta is attributable to
  the feed, not sampling noise. The ranker itself has no seed — it is
  deterministic.
- Every run carries a data-status ledger (D-20260804-002): no silent fallbacks.
- Metrics table per run (SEC 7.2) on full window AND trailing-1Y.
- **Gate:** relative bar holds on BOTH windows.

### 2.4 P4 — OOS falsification (purge-and-embargo)
- Expanding window: fold t uses data up to month m; embargoes months m+1..m+12
  (both from candidate scoring AND from the qual-gate inputs — purge removes any
  cached row with source_date inside the embargo); evaluates on the embargoed
  slice; advances m by 12m; repeat to the end of the dataset.
- This is the "PROVE it is beneficial" step: OOS excess = (baseline+feed excess
  vs SPY) − (baseline excess vs SPY) on embargoed slices.
- **Gate:** mean OOS excess > 0 AND majority of folds > 0. PIT tripwire tests
  (extend D-20260804-002 P6) assert no embargoed row can enter a decision.

### 2.5 P5 — Go/No-Go ruling
- Evidence package to CEO: registry rows (D-20260803-002 format), falsification
  report, conductor report, auditor identity check, cost ledger. CEO rules.
- No ruling, no merge, no integration. Default state is research-only.

## SEC 3 — Trend feed spec

### 3.1 Source taxonomy
| class | sources | status | gating |
|---|---|---|---|
| **Structured (immediate scope)** | SEC EDGAR new-filers (CIK resolver reuse), Reddit, StockTwits, ApeWisdom | P1 immediate | full gates P1→P5 |
| **Video (gated)** | Instagram, TikTok | sandbox only until P1 evidence | ≥1 qualitative-gate pass in P1, then full gates |
| **AI-model trend survey** | deterministic LLM prompt (temperature 0, cached, versioned): "top-10 trending subtopics in X" | concept-only | never allocation directly |
| **Company-exploration** | GitHub repo/star velocity, company_classifier | concept + ticker priming | full gates if ticker-emitted |

- Every row carries provenance (invariant 2): (topic, entity, source_id,
  volume_or_rank, sentiment, fetch_ts, source_confidence). `deg_registry.py`
  tags DEGRADED sources (D-20260804-002 pattern): unavailable source → zeroed
  contribution + ledger entry; never a hard stop for one missing API.
- **Fails-closed on insufficient data:** cross-source agreement requires ≥2 LIVE
  (non-degraded) independent sources; if fewer, that cycle emits no candidates
  (logged). Degraded sources can never be the second agreeing source alone.

### 3.2 Topic taxonomy (8, fixed)
`LLM | Statistics | Opensource AI | AI | Stocks | Applied Math | Quant trading | Datascience`
- Taxonomy is fixed in `discovery/taxonomy.py`; changing it is a config change
  (and a T3 if it expands candidate-relevant topics).
- Source feeds map into topics via explicit rules (hashtag/topic tags, subreddit,
  symbol lists); unmapped content is dropped from ranking (logged), never
  auto-tagged by a model.

### 3.3 Misinformation dampening (mandatory, unchanged from brief)
1. **Cross-source agreement** — ≥2 independent sources for trend-prime.
2. **Rank-vs-sentiment separation** — volume/rank may only PRIME; sentiment feeds
   the existing qualitative engine, never the priming score.
3. **Mandatory qualitative-engine + quant baseline tie** — SEC 5; trend can never
   override the gate.

### 3.4 Deterministic ranker (NO RNG — CEO instruction 4)
- `trend_score(entity) = Σ_src w_src · norm_rank_src + w_vel · velocity_z +
  w_cross · agreement_count + w_topic · topic_relevance
  − w_ad · ad_flag − w_clout · clout_flag`
- All weights pre-registered in `config/weights_discovery.yaml` (invariant 4),
  normalized to sum to 1.0 for the positive terms; penalty weights are separate.
- `velocity_z` = mention-count velocity (7d vs trailing 28d) z-scored within topic.
- `agreement_count` = number of live independent sources flagging the entity.
- Deterministic ordering: sort by score desc; tie-break by (topic priority,
  lexicographic ticker). `top_k` per cycle from config (default 10) enter the
  baseline screen; survivors enter the FULL pass (SEC 5).
- No `random`, no `np.random`, no epsilon, no stochastic draw — anywhere in
  `discovery/` (CI grep-asserted). The only seeds in the harness are for
  pre-existing pipeline stochastic components, identical across A/B runs.

### 3.5 Concept-vs-ticker separation
- **Ticker path:** SEC EDGAR new-filers, Reddit/StockTwits/ApeWisdom symbols, and
  video co-mentioned companies — validated via `validate_ticker` + CIK resolver →
  baseline screen → full pass (SEC 5) → candidate ledger.
- **Concept path:** non-ticker trends (e.g., **double-descent** — surfaced on IG,
  and previously seen in B-20260805-002 as an overfit capacity curve) go to a
  **research backlog** table: `concept_id, concept_name, topic, first_seen,
  sources[], linked_tickers (informational), hypothesis (nullable), status`.
  Concepts can ONLY prime hypotheses for future research briefs — **never
  allocation**. A concept may not become a candidate unless it later names a
  ticker that independently passes the full pipeline.

## SEC 4 — Video-signal hygiene (CEO specifics; IG/TikTok only)

Video is locked behind P1 evidence, and when unlocked it still passes through
these filters BEFORE ranking. Each filter is pre-registered in
`config/weights_discovery.yaml`; all thresholds are fixed before any run.

### 4.1 Clout-chaser filter (4.5a)
- A video is a clout-chaser if it is riding an already-exploded stock. Features:
  - `runup_ratio = price / 52-week-high` (floor pre-registered, e.g. 0.85),
  - `mention_velocity = mentions_7d / mentions_prior_28d` (floor, e.g. 3.0),
  - `explosion_lag` = days since the stock's run-up began (price first crossing
    the pre-registered threshold).
- **Exclusion rule (pre-registered):** exclude when runup_ratio AND velocity
  floors hold AND the video's mention spike LAGS the run-up start (i.e., the
  video is following the move, not leading it).
- Rationale: the edge, per B-20260805-002, is regime/fee structure, not
  retail-lag alpha; clout-chasers are exactly the anti-alpha retail-lag channel.

### 4.2 Niche / minimal-popularity scoring (4.5b)
- Prefer content with **low absolute popularity** (views ≤ ceiling, e.g. 100k)
  and a healthy (non-viral) engagement band — not trending pages.
- **Tandem/ecosystem extraction** (`discovery/ecosystem.py`): score content that
  explains HOW a company works in a chain — co-mentioned companies, and
  supplier/customer + monopoly/dependency relations classified via the existing
  qualitative engine (`Quantitative/company_classifier` + qualitative scoring).
  CEO example **ASML** = AI-enabling monopoly whose dependents (chipmakers) rely
  on it; the monopoly is the candidate, the ecosystem is the reason.
- Niche+ecosystem videos score higher than viral single-stock pump videos; viral
  pumps with no ecosystem content are excluded unless they meet the full pass.

### 4.3 Ad / sponsored detection (4.5c) — exclusion, not down-weight
- Heuristic OR-rule (pre-registered), any hit → excluded:
  - hashtags: `#ad`, `#sponsored`, `#spon`, `#partner` (case-insensitive),
  - affiliate/tracked-link patterns in caption/bio (`/ref=`, `bit.ly`,
    `linktr.ee`, shop URLs, `?utm_`),
  - brand-account signals (creator-verified + bio product links),
  - engagement anomalies: view-to-follower ratio or comment-to-view ratio outside
    the pre-registered healthy band.
- Ads must not distort stock signals: an ad-driven mention is treated as noise,
  never as a trend-prime.

## SEC 5 — Pipeline-passthrough rule (CEO instruction 3)

- **HARD INVARIANT:** NO mention becomes a candidate, and NO candidate becomes an
  allocation/backtest input, without a **FULL pipeline pass**:
  1. ticker validation + CIK resolution,
  2. existing qualitative engine (multi-source Bayesian fusion +
     qualitative_scoring + psychological state machine) — read-only invocation,
  3. quant baseline (D-20260802 discovery gate: liquidity/price/listing screen +
     delisted-retention survivor-free universe per D-20260804-002 P5),
  4. selectivity stage (D-20260803-001) + Glassdoor continuous tilt
     (D-20260802-FINAL).
- `discovery/passthrough.py` orchestrates the above by calling existing public
  interfaces; it does not reimplement scoring logic.
- **Audit/provenance trail** (`discovery/ledger.py` + `db/schema_discovery.py`):
  table `mentions` → `candidates` → `gate_passes` → `integration_decisions`,
  each row with `source_id, fetch_ts, decision_ts, reason_codes[]`. The audit
  module can trace any number to its inputs (invariant 2).
- **Two outputs, never conflated:** (a) exploration feed (dashboard/CEO:
  trend-primes INCLUDING rejected ones with reasons — research-only); (b) gated
  candidate list — the ONLY set that may touch harness/backtest, and only inside
  P3/P4 on the branch.

- `max_position_share_per_cycle: 0.20` (discovery-initiated positions),
- `top_k: 10` (ranker output before full pass).

### 7.5 Research-only fallback clause
- If ANY gate fails (P1 census degenerate, P2 determinism broken, P3 relative
  bar fails on either window, P4 OOS excess ≤ 0), the feed stays research-only:
  the exploration feed + dashboard output continue, allocation/backtest never
