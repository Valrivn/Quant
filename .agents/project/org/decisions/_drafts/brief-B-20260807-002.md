# Brief B-20260807-002 — Unblock the standard screen for the IG alpha comparison

**Owner:** big-pickle (Manager A) + gemini-planner (Manager B)
**Tier:** T3 (integrity-critical screen changes, cross-module)
**Related rulings:** D-20260807-001 (IG alpha experiment), D-20260807-002 (IG live feed)

## Problem

D-20260807-001's answer is blocked at the screen: **0% pass-through for every
lane** because both census gates are data-starved, NOT because of the IG
channel. IG lane is now seeded (31 live candidates), so only the screen blocks.

Three concrete defects found (research, 2026-08-07):

1. **Quant gate batching bug** — `discovery/census.py:182` and
   `discovery/ig_experiment.py:105` call `_quant_baseline_gate([ticker])` one
   ticker at a time. `quant_baseline_flags` computes `alpha_z` *within the
   frame* and needs ≥2 non-NaN alpha values (`discovery_screen.py:63`), so a
   single-name frame always yields `no_alpha_data`.
2. **Qualitative gate empty-input defect** — `_qualitative_gate` calls
   `AlternativeStrategyPipeline.run(ticker, {}, None, None)`. An empty moat
   composite yields `ema_60d = 0.0` (not None), so blended = 0.0 → `avoid` for
   every ticker. The docstring claims a neutral `hold`; reality is `avoid`.
   This is misleading: missing data should be neutral, not an avoid signal.
3. **Mahalanobis scale mismatch** — the L1 engine stores raw Mahalanobis
   distance (1.2–3.7), but `discovery_screen.py:52` expects a 0–1 value
   (`> 0.95` fails), so every fundamentally-scored name is rejected.

## Goal

Unblock the screen so a like-for-like **pass-cohort vs pass-cohort** alpha
comparison can run for IG (31 candidates) vs traditional (11 scraper cohort).
Same gates, both lanes, no fabrication.

## Design dimensions for the debate

- **D1 (quant gate):** batch the names frame across a run and attach real
  `alpha_3y_ann` + `cash_burn_months_pct` + `interest_coverage_ratio_pct`.
  Data source options: (a) cached `center/valuation_alpha/results.json` run_a
  (50 roster names, real but fixed-roster), (b) live per-candidate compute
  (yfinance + Ken French + SEC XBRL `fetch_companyfacts`), (c) hybrid
  (cached-where-available, live-otherwise).
- **D2 (qualitative gate):** (a) neutral-`hold` default on missing signals +
  wire cached DB signals (glassdoor/comparably/github/product_intel) for names
  that have them; (b) keep fail-closed `avoid`; (c) neutral pass-through only.
- **D3 (mahalanobis):** normalize engine output to 0–1 vs relax the floor.
- **D4 (integrity):** same gates both lanes; per-row provenance; document the
  qualitative-signal coverage bias (cached signals exist only for the ~10
  megacap cohort); never fabricate alpha or signals.
