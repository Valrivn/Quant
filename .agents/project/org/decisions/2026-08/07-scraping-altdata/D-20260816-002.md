# D-20260816-002 — Scraping Anti-Bot Strategy Engine Selection Gate (Fingerprint Audit)

- **Tier:** 3
- **Date:** 2026-08-16
- **Brief:** B-20260816-002
- **Ruling:** APPROVE (the fingerprint audit)

## Options considered
1. **Option A (nodriver patch):** Fix existing nodriver pipeline by pinning User-Agent and completing manual login once to seed a session cookie. (Proposer: big-pickle)
2. **Option B (CDP real browser driving):** Driving the real browser using chrome-devtools-mcp. (Rejected due to non-compatibility with unattended batch pipelines)
3. **Option C (Playwright MCP):** Re-platform to Playwright MCP with a persistent profile. (Proposer: gemini-planner)
4. **Hybrid (fingerprint audit gate):** Run a fingerprint audit (nodriver vs Playwright-stealth against Glassdoor's live Cloudflare wall) as the mandatory gate before engine selection. (Proposer: hermes-bridge)

## Positions
- **big-pickle (Position A):** Fix the nodriver pipeline first since UA pinning is already done and nodriver is native batch-capable, keeping Option B only as a manual refresh tool.
- **gemini-planner (Position B):** Re-platform to Playwright MCP with a persistent profile to ensure unattended execution and standardize browser automation.

## Disagreement map (if T3)
- Disagree on:
  1. Engine fingerprint survivability (nodriver TLS vs Playwright headless profile against Glassdoor Cloudflare/Turnstile) — this is the empirical gate that resolves the engine choice.
  2. Provenance re-testing cost (Option A uses existing wiring; Option C requires re-testing provenance hooks across all five scrapers).
- Consensus on:
  1. Option B (CDP/manual browser driving) is disqualified for production due to lack of automated unattended batch run compatibility.
  2. Unattended batch capability across ticker universe is required.
  3. Provenance invariant must be maintained (reliable, auditable data-status).
  4. User-Agent randomization was a root cause of cookie invalidation.

## Synthesis (hermes-bridge, if T3)
- Recommendation: Hybrid — run the fingerprint audit first; if nodriver passes, apply patch (approve A); if nodriver fails, re-platform to Playwright MCP (approve B/C); in either outcome, log cf_clearance TTL in data-status ledger immediately.
- Disagreements:
  - Substantive: Engine fingerprint survivability (nodriver TLS vs Playwright headless profile against Glassdoor Cloudflare/Turnstile) — this is the empirical gate that resolves the engine choice. Provenance re-testing cost is substantive: switching engines forces re-validation across all five scrapers before any data flows.
  - Stylistic: "one targeted action" (A) vs "consolidation" (B) is framing, not outcome.
- Rationale: Both positions agree Option B (CDP/manual browser) is disqualified for production; the live disagreement is which unattended engine survives Cloudflare's fingerprint scrutiny, and neither position has tested it empirically. A fingerprint audit against Glassdoor's live wall is the only honest resolution path — committing to Playwright before that test risks swapping one blocked engine for another. If nodriver clears the audit, the patch is one action with zero re-wiring cost; if it fails, the provenance re-testing sprint is the justified price.
- Risk: Cookie TTL expiry (cf_clearance ~30 days) silently breaks unattended batch runs if not tracked — TTL logging in data-status must be done before any option is declared production-ready.

## CEO ruling
> APPROVE the fingerprint audit. The audit is now authorized as the gate before engine selection.

**Rationale:** The fingerprint audit (nodriver vs Playwright-stealth vs live Glassdoor Cloudflare/Turnstile) is authorized as the mandatory empirical gate before engine selection, determining whether nodriver passes (Option A) or Playwright-stealth is adopted (Option C). The UA pin (part of Option A's patch) was already implemented and verified in `Qualitative/psychological/scrapers/nodriver_scraper.py` before the debate.
